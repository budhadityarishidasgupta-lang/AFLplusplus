# SB-49.P4-S Secure UAT Framework

## Safety model

The standalone runner reads only `SEARXNG_ENDPOINT`, `SEARXNG_API_TOKEN`, and `SEARXNG_APPROVED` from `.env` in its own Python process. It does not import Brain/provider code and does not access Alibaba, OpenAI, or Brave credentials. Values are held in memory and are never formatted into output. Requests target a fixed HTTPS Render hostname, reject redirects, use bounded timeouts and response sizes, and use credentials only as a Bearer header. The approval flag is observed but never changed; the runner only offers live mode when it remains disabled.

By default the runner is offline and marks production test cases **BLOCKED**. Live requests require both `--live` and `--credential-rotation-confirmed`; do not use those flags until credential rotation is explicitly confirmed by the owner. The runner never rotates credentials. Its tests use synthetic dummy values only.

## Run local preflight

From this directory:

```text
python scripts/uat_security_checks.py
python scripts/searxng_uat.py
python -m unittest tests.test_uat_security -v
```

The preflight emits scanner metadata (basename/category/count and aggregate baseline/new-change counts) and named PASS/FAIL checks; it never prints matching text. The UAT runner emits sanitized outcomes, statuses, counts, and durations. Request/exception details and headers are not logged. The repository-wide ignore policy may not ignore `.env`; verify `DOTENV_GIT_IGNORED` locally, and never add a real `.env` file.

## Local tracked-source scanner

`uat_security_checks.py` enumerates the Git-tracked inventory and scans eligible text files locally in process; it does not upload content or call an LLM. Output is limited to the tracked filename, finding category, count, and aggregate new-change/baseline counts. PR-delta classification compares against `origin/stable` and also includes staged, unstaged, and untracked candidate files. Findings in changed or candidate paths are PR findings; unchanged tracked paths are baseline findings. Inventory, unsafe paths, read, status, and diff-command errors fail closed. Pattern-based checks cover common API-key assignments and formats, bearer tokens, private-key headers, and tracked `.env` files. The scanner is heuristic and can miss novel, split, encoded, or otherwise unrecognized credentials; a clean result is not proof that no secret exists. Tests assemble synthetic credentials dynamically and scan temporary files so the assembled strings are not stored in tracked source.
