# Provider-scoped configuration and controlled UAT procedure

## Configuration architecture

The data path is `application -> provider-scoped ProviderConfiguration -> provider adapter -> separately authorized execution`. `brain_core.provider_config` defines allowlisted schemas for SearXNG, OpenAI, Alibaba Qwen, and Ollama. It does not snapshot the parent environment. Callers can pass an explicit provider-only mapping; otherwise it reads only that provider's listed environment names. Explicit mappings override provider-specific environment values. Unknown fields fail closed. No validation step connects to a provider.

Provider configuration records separate `configured`, `validated`, `availability_verified`, and `capability_enabled` states. Configuration and approval are independent. SearXNG requires an approved fixed HTTPS endpoint, a non-empty token, and an explicit `approved=1`; defaults are disabled. Search additionally requires the existing per-query UI approval, an authorization ID, a journey ID, and a successful one-time ledger claim. Provider availability remains unverified until an operator separately checks it. No automatic connectivity checks, browsing, ingestion, or external model fallback are initiated by configuration.

Secret-bearing fields are excluded from dataclass repr and redacted from `as_dict`; generic `get()` now rejects secret fields, with an explicit adapter-only accessor used by the SearXNG connector. Provider mappings reject unrelated keys. The SearXNG config reader reads only `SEARXNG_ENDPOINT`, `SEARXNG_API_TOKEN`, and `SEARXNG_APPROVED`; it does not import OpenAI or Alibaba credentials. Ordinary Studio continues to load dotenv only from its own explicit `.env` path, never from an ancestor or caller CWD. The isolated launcher constructs a clean allowlisted child environment and disables dotenv loading inside isolated Studio. This narrows accidental exposure but is not OS-level process isolation; same-user process access and file access remain.

## Session operating modes (P7D)

The Studio exposes `CONTROLLED` and `FREE_LEARNING`; `AUTONOMOUS_AGENT` is reserved and coerces to controlled mode. Controlled is the default and preserves the existing per-search approval widget and one-time ledger semantics. In Free Learning, explicit research requests may use a standing authorization limited to the current Studio session, public informational SearXNG queries, the existing query/result/time bounds, and the configured SearXNG provider. This does not authorize cloud LLM inference, messages, purchases, account changes, system commands, or autonomous mission execution. Select **Pause learning** to stop outstanding standing-authorized research; resume is explicit. Switching back to Controlled stops the standing mode. Search evidence remains untrusted and source-bound.

Learning candidates remain review-only unless existing explicit lesson approval is used. Approved lessons are local, attributable, retrievable and revocable through the existing lesson store; raw search results are not automatically promoted to approved memory. Free Learning research is attached to the current conversation session and its existing history; it does not copy private conversation content into the search query beyond the existing minimized explicit research request.

## Runtime credential delivery (P7C.1)

`brain_core.runtime_launcher` prompts for an explicit SearXNG token via standard-library `getpass`; callers may instead provide an explicitly constructed validated `ProviderConfiguration`. It never reads `.env` or extracts credentials from the parent environment. `getpass` suppresses echo where the Windows console supports it and warns/falls back where it does not. If hidden input cannot be confirmed, stop; a reviewed Windows Credential Manager adapter is a future option (`keyring` or native DPAPI-backed integration would require dependency/security review). Cloud deployments should use the platform secret manager through the same credential-source interface.

The launcher constructs a fresh child environment from only `PATH`, Python runtime keys and Windows runtime keys (`SYSTEMROOT`, `WINDIR`, `COMSPEC`, `PATHEXT`, `TEMP`, `TMP`), fixed local-mode controls, local Ollama loopback/model settings, the three documented SearXNG variables, and isolated runtime locations. Known OpenAI/Alibaba/Brave credential, endpoint, and model names are explicitly blanked (including aliases consumed by current readiness code) so inherited dotenv values loaded by imports cannot enable unrelated provider readiness. No blank Alibaba API-key variable is included in the child environment. The SearXNG credential is necessarily passed to the child process through its environment; this limits accidental inheritance, but Windows same-user process inspection remains a residual exposure. Arbitrary unknown provider variables are not copied. It uses argument-list process creation (`shell=False`), binds Streamlit to loopback, disables usage stats, and returns an owned process handle; shutdown signals and waits only on that handle. No `.env`, temporary credential file, or parent environment mutation is used. Python cannot guarantee secure memory erasure.

The child uses a non-secret fingerprint of the validated provider configuration to detect configuration changes between launch and Studio research. In isolated runtime mode, Studio does not load dotenv. In Controlled mode, research configuration and human per-request approval remain separately required, together with a one-time ledger claim. In Free Learning, the operator's explicit session mode selection supplies standing authorization for bounded informational SearXNG searches; the one-time ledger still prevents duplicate execution. A test search runner can be injected only when the explicit test-only `SOVEREIGNBRAIN_ALLOW_TEST_ADAPTERS=1` flag is present and the runtime is not marked isolated. The production launcher does not set this flag; isolated Studio ignores injected adapters and fails closed on mismatched configuration.

These controls are not OS sandboxing. A process running as the same Windows user may inspect environment/process memory, and the Studio process can read files accessible to that user. The filtered environment reduces accidental provider credential exposure but does not constrain file access or defend against same-user malware. The runtime folder must be reviewed for application-generated persistence before UAT. No actual credential input, Studio launch, or live query was performed in P7C.1. P7D engineering adds the mode selector and standing session research path; any live gateway check remains dependent on explicit operator credential entry and connectivity.
